# 横竖屏切换尺寸循环修复

版本 2026.10.11.3，Service Worker 缓存 v38。

用户报告横屏切回竖屏后棋盘持续抖动。此前简洁页面通过 ResizeObserver 测量开局说明、快捷设置和错误提示高度，再把测量值写入父级 CSS 变量，参与棋盘宽度计算；棋盘还使用尺寸容器查询。旋转会同时改变宽度、文本换行、动态视口和布局模式。代码存在观察结果回写上游尺寸的反馈路径；本次去除该路径，没有在用户设备上重现并确认某一特定浏览器的根因。

简洁页面现在用原生 flex 布局，控件保留自身高度，棋盘区域得到剩余空间；正式开局的小屏横屏继续使用侧边 grid。所有测量高度变量及对应控件尺寸观察器已删除。主棋盘和自定义摆局的棋盘框绝对定位于一个独立分配的区域，子棋盘尺寸不参与区域的固有高度。统一的 board-layout.js 只观察这个区域，根据其宽高中较小的值设置棋盘框的整数宽度。重复通知不重复写入，半像素以内变化不触发更新；隐藏区域的零尺寸与无效尺寸被忽略，重新显示后仍能适配。棋谱和截图预览继续保持自己的尺寸。

验证使用 Node/jsdom，按用户要求没有浏览器测试或设备实测。专项检查涵盖手机和 iPad 尺寸的竖屏→横屏→竖屏序列、1,000 次重复/边界小数通知、隐藏后恢复、自定义摆局、预览隔离，以及静态 CSS 的独立尺寸关系。四个实际模式入口检查棋子 DOM、存档和引擎搜索次数保持不变，且没有控件尺寸写回父级。软件回归通过不能替代用户设备上的最终视觉确认。

运行：`node --test tests/board-layout.test.js`、`node --test --test-name-pattern='rotation notifications' tests/app-lifecycle-dom.test.js`、`npm test`、`npm run check`。

结果：10 项新增尺寸／入口回归检查通过；全部 295 项 Node 检查通过，语法、引擎与权重完整性检查通过。
