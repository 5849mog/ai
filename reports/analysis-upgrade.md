# 分析区上线后的补充验收与缓存升级修复

旧版页面的浏览器 HTTP 缓存仍新鲜时，原 `Cache.addAll` 会把旧首页和旧 app.js 装入新版离线缓存。使用真实 v11 页面、设置一小时 HTTP 缓存后切换到 v12，已复现新离线缓存内没有新增分析 UI 的问题。

v13 对界面、脚本、样式等可变核心文件使用 `Request(..., { cache: "reload" })`，确保每次安装新版本时取得新的字节。固定版本的引擎文件保持默认 HTTP 缓存策略。首页和关于页同步使用 `styles.css?v=13`，旧离线缓存仍由激活流程清理。当前棋谱及本机分析记录不变，三项分析的样式与交互设计不变。

新增 `npm run test:upgrade` 的自包含回归场景，模拟浏览器已缓存旧首页、旧脚本，并验证 v11 / v12 升级至 v13 后核心文件与最新源码逐字节一致、旧缓存移除、当前棋局保留。随后断网刷新，使用真实 Rapfi 完成人机落子、胜率更新和悔棋。四组场景通过，55 项单元测试及语法、引擎校验通过。

补充检查还通过了四组边界场景：合法 225 手平局的结束与刷新、连续悔棋后的历史截断和刷新、三位手数的移动端曲线排版、搜索中取消推荐。长曲线压力检查使用合成评估点，棋谱本身由真实规则验证；取消推荐使用确定性协议测试替身，未作为棋力验证。

机器可读记录见 [analysis-upgrade.json](./analysis-upgrade.json)。
